# Pincer

Новый desktop-клиент на **Electron + React** для существующего OpenClaw Gateway.
Backend написан с нуля. OpenX остался отдельной нетронутой папкой и используется
только как источник визуального оформления.

## Подключение, чат, память и обновления

Реализовано:

- два прямых WebSocket-соединения: `operator` для управления и `node` для устройства;
- авторизация токеном или паролем, подпись серверного challenge ключом Ed25519;
- постоянная идентичность Pincer и отдельные токены ролей в зашифрованном хранилище;
- независимые состояния соединений, ошибки авторизации, ожидание pairing с ID запроса,
  несовместимость протокола и автоматическое переподключение после разрыва;
- восстановление подключения после перезапуска приложения;
- сведения об устройстве: `device.info` и `device.status`;
- реальные выданные права, версия сервера и согласованный протокол в интерфейсе;
- окно Electron, светлая/тёмная тема, RU/EN, перенесённая карточка подключения и
  оболочка с боковой панелью и автоматическим переходом после подключения;
- список чатов, новые сессии с запросом полного доступа, сообщения, потоковый ответ,
  остановка конкретного запуска и восстановление истории после переподключения;
  состояние каждого активного запуска закреплено за своей сессией: при переходе
  между чатами метка «В работе» и таймер не теряются и снимаются по финальному событию;
- чтение и редактирование `MEMORY.md` выбранного агента на Gateway, защита от
  обнаруженных конфликтов редактирования, поиск через серверный `memory_search`;
- проверка embeddings через `doctor.memory.status`, честное различение
  семантического поиска и поиска по словам;
- отдельный установщик Windows и обновления из `ZitZdorovo/Pincer`.

В рабочей версии (ещё не опубликованной отдельным релизом) также добавлены:

- изменяемая ширина sidebar, поиск, закрепление, переименование и удаление чатов;
- проекты Gateway и создание чата в реальной рабочей папке, выбор агента;
- отдельная страница настроек, системная тема, размер шрифта, reduced motion,
  горячие клавиши, подписи агентов и запуск установленной версии вместе с ОС;
- модель и глубина размышлений из возможностей сервера, поиск по переписке,
  зашифрованные текстовые черновики, вложения и безопасные inline-превью изображений;
- создание/редактирование агентов и personality-файлов; список каналов и управление
  работающими аккаунтами; поиск/установка/включение навыков; CRUD и запуск cron-задач;
- формы провайдеров моделей и embeddings: адрес, модели, новый ключ, проверка хеша
  конфигурации перед записью, без возврата сохранённых ключей в интерфейс;
- дерево файлов сессии, текстовый редактор с серверной проверкой хеша, preview картинок;
- карточки Gateway approvals: контекст действия и адресат, разовое разрешение/отказ,
  дополнительное подтверждение постоянного правила, срок действия и повторная проверка
  запроса перед решением. При наличии объявленных сервером методов восстанавливаются
  ожидающие exec/plugin-запросы; внешние подтверждения не обходятся.

Полное соответствие OpenX пока не достигнуто. Проверки новых функций используют
изолированный имитатор Gateway, а не профиль и сервер пользователя.

Нет встроенного OpenClaw, локального Gateway, ACP-процесса, запуска OpenClaw CLI,
унаследованных конфигов, данных или канала обновлений OpenX.

**Полные права не означают готовые команды.** Запрашиваются все перечисленные
операторские права: `admin`, `read`, `write`, `approvals`, `pairing`, `questions`.
Фактически выданные права определяет Gateway. Системные команды и файлы пока
не реализованы и не объявляются в возможностях ноды. Обход pairing и UAC не предусмотрен.

## Запуск для разработки

Требуется Node.js 22.19+ (для сборки; пользователь будущей готовой сборки будет
использовать встроенный runtime Electron).

```sh
npm ci
npm run dev
```

После сборки повторный запуск: `npm start`.

Укажи адрес Gateway и введи секрет **в приложении**. Для сервера нужен `wss://`;
`ws://` разрешён для локального туннеля на `127.0.0.1`, `localhost`, `::1`.
Для самоподписанного сертификата укажи проверенный SHA-256 fingerprint.
Не помещай токены в URL. При запросе pairing подтверди именно это устройство
в интерфейсе Gateway и нажми «Повторить подключение».

На Windows отдельное хранилище: `%APPDATA%/Pincer/gateway.vault`, шифрование
через Electron `safeStorage`/Windows DPAPI. Ключи и секреты не отдаются обратно
в Renderer. Папки OpenX и `.openclaw` не читаются.

На текущем этапе закрытие окна в Windows завершает приложение и отключает ноду.
Трей и постоянная фоновая служба пока не реализованы.

## Совместимость

Клиентские библиотеки зафиксированы на `2026.8.2`. Operator использует протокол 4,
нода — поддерживаемое библиотекой окно 3–4. Это **не** гарантия работы с любым
релизом OpenClaw: рабочий Gateway пользователя пока не проверен.
При несовместимости показывается ошибка; CLI-fallback отсутствует.

Версии Pincer и транспорта ноды разделены: `client.version` — версия реально
включённого standalone SDK; `client.buildId` — `pincer-<версия приложения>`.
Версия не подменяется значением, полученным от сервера. При изменении версии
Gateway приложение проверяет собственный канал обновлений. Для нового SDK нужен
новый протестированный релиз Pincer: произвольный код с сервера не загружается.

## Память

Pincer не содержит локального индекса и не запускает `memory sync`. Файл памяти,
embeddings и индекс принадлежат Gateway. Если сервер не настроен для векторного
поиска, страница памяти показывает ошибку провайдера. Сохранение файла не означает,
что индекс уже готов. Индексацией и её расписанием управляет сервер; поиск вызывает
его штатный инструмент. Настройки и ключи провайдера меняются только через явное
сохранение формы пользователем, с проверкой актуального хеша конфигурации и
поддерживаемого сервером пути схемы (`memory.search` или legacy-путь).
После смены модели embeddings может потребоваться переиндексация на сервере;
успешное сохранение настроек не означает, что проблема `memory sync` полностью решена.
Перед записью сверяется хеш свежего файла. Это защита от обнаруженных конфликтов,
не атомарный серверный compare-and-swap: Gateway такого контракта здесь не даёт.

## Установка и обновление

Установщик: [Releases](https://github.com/ZitZdorovo/Pincer/releases).
Описание текущей версии: [RELEASE_NOTES.md](RELEASE_NOTES.md).
Первую установленную версию нужно поставить из `Pincer-Setup-…-x64.exe`.
Запуск через `npm start` — режим разработки, он не обновляет исходники автоматически.

В установленной версии: «Обновления» → «Обновить». Появится плашка с прогрессом;
после успешной загрузки и проверки SHA-512 приложение завершится, установщик
обновит Pincer и запустит его снова. При ошибке загрузки приложение остаётся открытым.
Перед обновлением надо сохранить память и отправить/очистить черновики сообщений.
Проверки релизов выполняются при запуске, смене версии Gateway и каждые четыре часа.
Установка начинается по нажатию кнопки. OpenClaw на сервере не обновляется этим механизмом.

Сертификат Authenticode пока не настроен: Windows может предупреждать о неизвестном
издателе. Проверка контрольной суммы не заменяет подпись издателя.
Рабочий процесс `.github/workflows/release.yml` проверяет тесты и публикует NSIS +
`latest.yml` + blockmap при отправке тега `v<версия package.json>`.
Локальная сборка: `npm run dist:win`. До подключения сертификата изменение и
подпись исполняемого файла отключены, поэтому сборка не требует специальных прав Windows.

Проверенные официальные контракты:

- [Клиент Gateway](https://docs.openclaw.ai/gateway/clients)
- [Протокол](https://docs.openclaw.ai/gateway/protocol)
- [Подтверждение ноды](https://docs.openclaw.ai/gateway/pairing)

## Проверки

```sh
npm run typecheck
npm test
npm run test:e2e
```

Тесты используют локальный имитатор Gateway и временные профили. Есть проверки
подписи challenge, разделения ролей, отсутствия секретов в UI, шифрования на диске,
pairing, неверного токена, несовместимости, переподключения и перезапуска Electron.
Снимки окна записываются в `artifacts/`. Тесты обновлятора проверяют порядок
«загрузка → завершение → тихая установка и перезапуск» с заменённым установщиком.
Они не заменяют проверку перехода между двумя настоящими установленными релизами.
Для изолированной проверки упакованного приложения поддержан стандартный параметр
Electron `--user-data-dir=<абсолютная временная папка>`.

## Пока не реализовано

Локальное системное исполнение ноды (сейчас только `device.info`/`device.status`),
общие локальные файлы, автоматическая публикация нового SDK вслед за OpenClaw,
подписанные Authenticode-релизы и проверенный переход между двумя установленными
версиями. Также остаются OAuth, настройка/QR каналов, полное управление навыками,
очередь сообщений, карточки планов и вопросы агента, PDF/Office/browser,
вложенные папки и drag/drop, а также окончательная визуальная сверка с OpenX.
Не все функции Gateway одинаково доступны на разных версиях; отказ сервера не
превращается в имитацию успеха. Вложения черновиков пока не сохраняются на диск.

## Настройки и лимиты провайдеров

В «Настройки → Поставщики моделей» рядом с API есть вкладка «Лимиты».
Gateway сообщает собственные квоты через `usage.status`. Для моделей через
OmniRoute можно добавить его URL и management token — не токен OpenClaw.
Подключение проверяется перед сохранением, секрет шифруется ОС, сохранённое
значение не возвращается в интерфейс. Лимиты доступны также в кружке возле модели.

Настройки имеют боковую панель и ограниченную область содержимого как в чате.
Подключение оформлено той же поверхностью и отделено вкладкой от полной конфигурации
Gateway, поэтому форма соединения и тысячи серверных параметров больше не смешаны.
Добавлены типографика, акцент, ширина переписки, сворачивание инструментов,
уведомления внутри приложения. Цвета обновления следуют теме. Время ответа
измеряется до завершения, сохраняется после перечитывания истории и перезапуска.
Курсор остаётся стрелкой; выделение и копирование переписки/preview сохранено.
Pincer запрашивает у подключённого Gateway полную `config.schema`: все 41 блока
OpenClaw 2026.8.2 и вложенные параметры редактируются внутри клиента, без переходов
в Control UI. Профиль, устройства, approvals, журналы и память подключены через
свои Gateway-методы; новые корневые блоки схемы автоматически появляются в
«Расширенных». Секреты не возвращаются в окно приложения.
Действующий агент выбирается в выпадающем меню заголовка чата; отдельная кнопка
`@` в composer удалена. Выбор по-прежнему создаёт настоящую дочернюю сессию агента.
Интерфейс настроек сверялся с установленной панелью OpenClaw 2026.8.2.

## Происхождение UI

За основу взяты `src/styles/globals.css`, конфигурация Tailwind
(переименована в `.cjs`) и исходные UI-примитивы. Основные страницы, Sidebar,
TitleBar, Composer, окна/меню и личные настройки перенесены из исходников OpenX
в `src/donor`, а не воссозданы по сходству. Все обращения к данным заменены
типизированными адаптерами Pincer; старые stores, ACP и host API не используются.
Для сообщений используются исходные настройки Streamdown, подсветки кода и KaTeX.
Панель файлов использует разметку ArtifactPanel/WorkspaceBrowserBody с новым
удалённым чтением и сохранением.
